# Architecture & module contracts

A first-person cab ride along a street tram line through a limestone city street.
Browser app, three.js r186 (vendored, `vendor/three`), plain ES modules with no build step.

Run: `python3 serve.py` (or any static server at the repo root) and open `http://localhost:8080/`.

## Hard rules (apply to every file)
- **Blind comparison**: never write any AI model name, AI company name or "generated by" wording anywhere: code, comments, file names, titles, metadata, commit messages, asset metadata (glTF `generator`/`copyright` fields too).
- Only `reference/*.jpg` describes the scene. Do not search the web for this street/city or for existing models of it. Never use the reference photos as textures.
- All geometry and textures are procedural (JS at runtime, or Blender/Python scripts in `tools/`), or freely licensed assets recorded in `docs/ASSETS.md` with their licence.
- Photoreal is the goal: real-world scale, PBR values, no toon/flat/low-poly look, no primitive placeholders in the final result.
- Content is deterministic: identical on every visit (see `src/core/rng.js`).
- Keep all work inside this repository. Scratch output goes to `.work/` (git-ignored).

## Tooling
- `tools/shoot.py`: headless Chrome on the GPU. It starts a private static server, opens the app, waits for `window.__ready`, saves screenshots and prints console errors and `stats` (fps uncapped, frameMs, gpuMs, draw calls, triangles, per-module chunk build ms).
  - `python3 tools/shoot.py --params "s=420&tod=0.55" --out .work/shots/x.png`
  - `--shots 4 --interval 0.5` makes a sequence. `--eval "<js>"` evaluates and prints (it may be an async IIFE). `--settle 3` waits longer. `--pre "<js>"` runs right after ready.
  - Ride timing: `python3 tools/shoot.py --params "s=1700&speed=45" --shots 0 --settle 30 --hitches` resets the frame statistics at ready and prints the frame-interval percentiles and the hitch log at the end (see Frame timing). Screenshots stall frames, so time rides with `--shots 0`.
  - `--heapprof 30` samples JS allocations (garbage included) from ready to the end and prints the top 30 allocation sites with MB and MB/s. Compare runs per frame (site MB / `frames.n`), not per second. `--profile <dir>` keeps a Chrome profile (and its GPU shader cache) between runs.
  - Timing runs (`--hitches`, `--heapprof`) print the machine's load at the start and the end: load average per core, headless browsers running, GPU utilisation. Other agents often capture on the same machine, so CPU cores and the GPU are shared: judge frame times on the `usual` values and the `contention` / `gpu-wait` causes in the hitch log, repeat a run before blaming a module, and run budget checks serially on a quiet machine. Structural counts (allocations per frame, draw calls, triangles, upload bytes, program re-evaluations) are reliable under load; milliseconds are not.
- `tools/dk <cmd>`: runs a command in the Docker tools image (`docker/Dockerfile`: Blender 4.5 LTS, Node 24, Python + numpy/scipy/Pillow, ImageMagick, ffmpeg, gltf-transform), with the repo mounted at `/work`.
  - Blender: `tools/dk blender -b --factory-startup -P tools/blender/<script>.py -- <args>`. Write outputs to `assets/<area>/`.
  - `DK_GPU=1 tools/dk ...` adds the NVIDIA GPU (Cycles baking). `tools/dk node <file.mjs>` runs plain-JS checks (no `three` import map there).
- URL parameters (core ones in `src/core/params.js`): `s`, `tod`, `fov`, `speed` (starting speed; the auto driver then picks its own cruise), `auto`, `freeze=1`, `rec=<fps>` (offline recording: fixed time steps, frames stepped by `app.recStep(n)`, see `tools/record.py`), `capture=1`, `only=a,b`, `skip=a,b`, `view=s,d,h,yawDeg,pitchDeg` (free inspection camera in route coordinates; yaw + turns left), `q=low|med|high`, `debug=1`, `seed`.
  - Isolate your module while iterating, e.g. `only=street` (core modules materials/env/train/cameraRig always load). Add `post` to `only` to include post-processing and `farfield` to include the far field; `skip=farfield` drops it.
  - Inspection and A/B switches: `sky=streaks|cumulus|haze` (cloud and aerosol regime), `tram=<s>` (first oncoming tram's nose), `prof=1` (post's per-section GPU timers in `app.post.timings`), `taa=0`, `taaj=<px>`, `sharp=<k>`, `debug=1` (also `stats().badPixels`), `ffnear=<m>` (start the far field nearer, to compare it with the real chunks), `glbox=0` (core's unboxed uniform upload off, see Frame timing), `audio=1`, `audiocache=0`. Light and sky inspection: `mie`, `mieh`, `miealb`, `mieg`, `alt`, `hlev` (env), `hslope`, `skychroma`, `skysat` (post). Module-private debug switches (`humans_*`, `crowd_*`, `crowdCheck=1`, `veg*`, …) are described in each module's header.
  - Close-up inspection: `view=430,9,1.7,-60,8` stands on the right sidewalk at s=430 and looks right-ish towards the facades. Yaw −90 looks straight at the right-hand facades and +90 at the left-hand ones.

## Coordinates & conventions
- Metres, Y up, three.js right-handed. 1 UV unit = 1 metre on every library material, so geometry UVs must be in metres. Materials handle texture scale.
- **Route coordinates** `(s, d, h)`, see `src/world/route.js`. `s` is distance along the street centre line (wraps at `route.length`, about 6 km, a closed loop). `d` is the lateral offset, + to the right of travel. `h` is height above the paving. Rail tops are flush with the paving at h = 0.
  - `route.toWorld(s, d, h, out?)`, `route.sample(s, out)` → `{pos, tan, tanH, right, heading, curvature, grade}`, `route.heading(s)`, `route.curvature(s)` (+ = left curve), `route.elevation(s)`, `route.grade(s)`, `route.offsetScale(s, d)` (= 1 + κd, arc-length scale of an offset line), `route.wrap`, `route.delta(a, b)`, `route.project(x, z, sHint)` → `{s, d}`, `route.segments`, `route.segmentAt(s)`. Pass `out` in per-frame code: without it toWorld allocates a vector.
  - `object.rotation.y = route.yawAt(s)` makes local −Z point along travel (+X to the right). `rotation.y = route.heading(s)` makes local +X point along travel.
  - Elevation: gentle periodic rolling, periodic hills (`route.hills`) and mesas (`route.mesas`: an eased climb at a steady grade, a level top, an eased descent). The default start (s = 25) stands in a shallow sag at the foot of the main avenue, which climbs 21 m at about 5.8 % from s ≈ 240 to 510, levels off at about 600 (the first stop) and descends from 740 to 1300. The steepest grade on the loop is 5.9 %.
- Street cross-section (`src/core/config.js`): standard gauge 1.435 m. Rail centre lines are at `±RAIL_CENTER` (0.7455) from each track centre. Track centres are at `d = ±TRACK_OFFSET` (1.6). The camera rides the **right** track (d = +1.6). The paved track corridor spans `|d| ≤ TRACK_ZONE_HALF` (3.4), with a light stone edge band `EDGE_BAND_W` on each edge. Pole line `POLE_D` = 3.95, tree line `TREE_D` ≈ 5.15. Facades sit at `|d| = layout.halfWidth(s, side)` (≈ 11–13.5 m). Driver eye: `EYE_HEIGHT` 2.75 m. Contact wire: 6.0 m.
- **Ground**: `route.surface(s, d)` shapes the ground outside the track corridor: sidewalk cross-fall, a hillside tilt and settlement undulation, level beyond about the facade line. `route.toWorld(s, d, h)` and `route.groundY(s, d)` include it, so always place objects with toWorld (h = height above the local paving). Never use `route.sample().pos` plus your own offsets for ground contact. The street mesh adds its own millimetre detail (gutters, crowns) on top: `app.systems.street.heightAt(s, d)` is the paving as drawn.
  - Within 0.9 m of a facade the paving meets the building's own ground line (lot frame chord, `plan.groundAt(u)`). Objects standing against facades use `plan.groundAt` or `street.heightAt(s, d)`, not toWorld with h = 0. Corner returns and cut faces have a varying `groundAt(u)` (`frame.ground0 ≠ frame.ground1`), eased into the side street.
  - Side streets: `street.mouth(c, side)` → `{start, along, dirOut, len, hw, half, road, sw, kerbH, rampX, level}`, the mouth frame of cross street `c` (a point at mouth coordinates (a, x) lies at `start + along·a + dirOut·x`: a across the side street, x out from the main facade line), and `street.sideHeightAt(c, side, a, x)` its paving height (carriageway a kerb below the sidewalks, ramped up from the mouth). Things up a side street are placed and drawn in this frame.
- **Facade frame** (per building lot): `lot.frame = {origin, uDir, nDir, up, width, ground0, ground1, floorRef, matrix}`. `u` runs along the facade and increases to the viewer's right when looking at the facade from the street. `v` is up from `floorRef`. `w` points out of the wall toward the street, so recesses are at w < 0. `frame.matrix` maps (u, v, w) to world. The frame is right-handed, so CCW winding seen from the street is front-facing. Ground (paving) height along the facade is `plan.groundAt(u)`, which is ≤ 0 because the street slopes.

## Layout (shared master plan): `src/world/layout.js`
Deterministic and computed once. **Read placements from here and never invent overlapping ones.**
- `stations[]`: `{id, s, len, stopS, platforms:[{side, s0, s1, d0, d1, h}]}`. Side platforms are 2.9 m deep and 0.30 m high, on both sides of the corridor.
- `crossovers[]`: `{s0, s1, len, from}`, a single crossover between the tracks. `from:+1` means facing points on the ride track at s0 diverging to the left track by s1.
- `crossStreets[]`: `{s, width, side (0 both | ±1), depth, angle, junction?}`. No lots, trees or poles in the mouth.
- `lots[]` (main street): `{id, side, s0, s1, len, d, seed, depth, cornerStart, cornerEnd, cornerU0, cornerU1, frame, cafe?}`. `sideLots[]` line the cross streets: `{..., sideStreet:true, cross, edge, x0, x1, frame}`. `lot.cafe` is the index of the lot's terrace in `cafes`.
- `poles[]`: `{s, side, d, lamp, banner}`, shared by lamps and catenary (catenary draws a banner on about a third of the flagged poles).
- `trees[]`: `{s, side, d, seed, height, crown, mature}`: young trees 5.0–7.2 m tall with 2.6–3.8 m crowns, about 18 % mature (8–11 m, 4.5–6.5 m). Vegetation picks the drawn species, age and size from these with its own draws (about one old tree in ten on the avenue, s < 1500, and one in five elsewhere; young crowns drawn a little narrower than planned), so clearances computed from the layout values are conservative.
- `cafes[]`: `{id, lot, side, s0, s1, dIn, dOut, style ('umbrella'|'open'|'awning'), chairStyle, tables:[{s, d, shape, chairs:[{s, d, yaw}], dressed, places}], umbrellas:[{s, d, size, color}]}`. Chair yaw is a route-relative heading offset, and the chair faces the table.
  - A terrace belongs to one shop: 5–14 m of sidewalk centred on a ground-floor shop of its lot (else its entrance), at most 10 tables (about 4 on average) in one loose row, sometimes two (a second row only where it leaves a walking band beside the tree line). About 250 terraces on the loop.
  - Terraces come in runs of 2–4 neighbouring lots of a block (1–3 elsewhere). About 28 % of the frontage is café on the main avenue (s < 1500; its right-hand side a little more), within 130 m of a stop and at cross-street corners, and about 10 % elsewhere (error diffusion per side keeps it steady). The right-hand sidewalk ahead of `defaultStartS` always opens with a run. About 70 % of terraces are `'umbrella'` style; two terraces without umbrellas never follow each other in a run.
  - `umbrellas[]`: square market umbrellas packed edge to edge (about 0.3 m apart) over the whole terrace, `size` 3.0–4.0 m, one `color` per café (cream, white, a few navy, the odd sand or burgundy). `d` keeps the canopy at least 0.36 m inside the facade line, and `dIn` always lies at least 0.5 m beyond the umbrella row.
  - Furniture writes `tables[].dressed` (0 bare, 1 laid, 2 in use) and `tables[].places` (chair indices with a place setting) at init, and relaxes chair and umbrella positions and writes them back. The crowd seats patrons at the set places of dressed-2 tables first, then occasionally 1, never 0.
- `furniture[]`: `{type, s, d, yaw, ...}`. Types: bin, bench, bollard, planter, kiosk, advertColumn, bikeRack, infoBoard, shelter, ticketMachine, stopSign.
- `obstacles[]` (for the crowd): circles `{kind:'circle', s, d, r}` and rects `{kind:'rect', s0, s1, d0, d1}` (cafés, platforms, shelters carry their id). Query with `obstaclesNear(s, range)` or `inChunk('obstacles', i)`.
  - `layout.addObstacles([...])` registers obstacles for free-standing things a module places itself (A-frame boards, goods stands…): they join `obstacles` and the chunk buckets (obstacles pushed straight into `obstacles` reach the buckets at the next lookup too). Call it in `init`: the crowd reads the obstacles in its own init, which runs after every world module's.
- Per-chunk lookup: `layout.inChunk(kind, chunkIndex)` for kind in lots, sideLots, poles, trees, cafes, furniture, obstacles, crossStreets, stations, crossovers. Helpers: `halfWidth(s, side)`, `chunkIndex(s)`, `isInStation(s, m)`, `isInCrossStreet(s, side, m)`, `isInCrossover(s, m)`, `nextStation(s)`, `defaultStartS`.

### Facade plans: `src/world/facadePlan.js`
`facadePlan(lot)` returns the architectural plan of a lot (cached, deterministic): floors, bays, openings, balconies, string courses, cornice, parapet, roof, rooftop clutter, signs, flags and style. It is shared by `buildings`, `facades`, `ironwork`, the crowd (doors) and the far field. Extending it is fine; renaming fields is not.
- Openings: `{id, floor, bay, uc, w, y, h, kind (shop/door/window/balconyDoor), top (flat/round/segment/pointed), rise, recess, shutters, lit, curtain, awning, ac, flowerBox, backDepth}`. `o.backDepth` is the interior box depth behind the glazing. `shutters` is `'roller' | 'open' | 'closed' | 'none'` (null on older openings), `roller` the share of a roller shutter let down (0..1), `ac` a split unit under the window.
- `plan.style`: `{era, tint, courseH, blockL, tooled, rusticGround, quoins, pilasters, surrounds, windowTop, shopTop, frameColor, shutterColor, finish, render, stone}`.
  - `tint` is the absolute stone tint (cream `[0.86, 0.80, 0.68]` = the library texture as baked); buildings use `(tint / cream)^1.25` as the vertex tint. Weighting: honey and golden on about half the lots, pale and grey on about a fifth (`materials.meta['stone.ashlar'].tintWeights`).
  - `finish: 'render'` (else undefined: ashlar) marks a rendered, colour-washed block (about half the modern ones): `render = {color (multipliers on the plaster albedo), from (v where the render starts: top of the first string course, or the first floor)}`, and `stone` holds the stone tint of its dressing and stone-clad shop floor. For such lots `tint` holds the render's colour expressed as a stone tint, so anything coloured from the tint follows the wash; parts that are stone (shop recess linings, stone balcony slabs and corbels) should use `style.stone`.
- `plan.coursing {ch, v0}`: sills aligned per floor, heads snapped to courses.
- `plan.cuts` and `plan.returns[]`: corner returns and chamfer faces with their own frames (`isCut`, `cut`). Facades must iterate `plan.returns` generically.
- `plan.upper`: a set-back volume on a flat roof (penthouse or a later addition of several storeys), with its own facade frame (front at w = −setback): `{setback, u0, u1, width, depth, v0, floorH, floors, material, color, openings, frame, addition, balconies, sides, tower, mural, selfDressed: true}`. Buildings dresses it itself, so other modules may ignore it.
  - `balconies`: `[{u0, u1, y, depth, slabT, solid, floor}]` on additions.
  - `sides`: `[openings of the u = 0 side, openings of the u = width side]` or null. A side face's frame follows buildings' `sideFrame`: on the u = 0 side u runs from the back to the front, on the u = width side from the front to the back; the normal points outwards.
  - `tower: true` on the view-terminating lots (`terminusLots()` lists them): a plain modern block of several more storeys, windows on every side, and on some a painted mural `mural = {e (side), k (mural texture, buildings sink key 'mural<k>', material 'buildings:mural<k>'), u0, u1, v0, v1}` on the side facing back down the street.
- `plan.relief` (what the masonry puts on the wall face), `archSegments(o, q)`, `archPoint`, `openingOutline`, `ornament(plan, rng)` and `archRise` are exported helpers. Backdrop lots from `buildings.extraLots()` are dressed by facades (no `selfDressed`). Buildings owns door thresholds and steps. Facades dresses café 'awning' terraces with a continuous awning (hem about 2.7 m).

## Module system: `src/main.js`
Each module is a file whose default export is an object:
```js
export default {
  name: 'street',
  lods: [0, 1],                // optional: detail levels this module builds (default [0, 1])
  async init(app) {},          // optional, once; registry order (materials, env, post first)
  build(chunk, app) {},        // optional: return an Object3D for this chunk (or null)
  dispose(obj, chunk, app) {}, // optional: default disposes non-shared geometries
  update(dt, app) {},          // optional, per frame: train → cameraRig → others in registry order
};
```
- Modules are loaded with dynamic `import()`. A module that throws at load, init, build or update is logged and disabled, and the rest keeps running. **Never statically import another module's file.** Use `app.systems.<name>` (or the aliases `app.materials`, `app.env`, `app.post`, `app.train`, `app.cameraRig`, `app.crowd`, `app.humans`, `app.audio`, `app.ui`, `app.trams`). Static imports are fine for `src/core/*`, `src/world/{route,layout,facadePlan,streaming}.js` and `vendor/three`. A pure helper of another module (for example facades' `shopDecision(plan, o)` in `src/world/facades/shops.js`, the door, setback and roller-shutter decisions exactly as the facades draw them) may be loaded with a guarded dynamic `import()` that falls back when it fails.
- `chunk = {index, s0, s1, lod, group, rng(tag)}`, with CHUNK_LEN = 40 m. Detail levels: `lod` 0 within `LOD0_DIST` (200 m), 1 out to `VIEW_AHEAD` (680 m) and 2, the far field, from there to `VIEW_FAR` (1400 m, `src/core/config.js`). A module is asked to build the levels in its `lods`; only the far field (`src/core/farfield.js`, core) builds lod 2. Chunks are rebuilt at a finer level as they come close.
- `build` must be fast: **target < 3 ms per chunk per module** (the streamer time-slices about 7 ms per frame across modules). Precompute shared geometry in `init`. Reuse geometries (`geometry.userData.shared = true` so they are not disposed). Merge per material with `MeshBatcher` (`src/core/geom.js`) or use InstancedMesh per chunk.
- `app`: `{THREE, renderer, scene, camera, canvas, params, U, events, route, layout, world, systems, time, dt, realDt, frame, startS, cameraS, perf}`. `app.dt` is 0 when frozen, and `app.realDt` is the wall-clock delta.
- `window.__app.stats()` returns perf counters. Startup builds chunks within 240 m (and primes the far field), compiles every program, then sets `window.__ready`.

## Shared runtime
- `src/core/uniforms.js` `U`: `uTime`, `uWind` (xz dir), `uWindStrength`, `uNight` (0 day to 1 night: drives lamps, shop and window emissives), `uSunDir`, `uSunColor`, `uCameraPos`, `uSpeed`. Inject them into custom shaders via `onBeforeCompile` (`shader.uniforms.uTime = U.uTime`). `env` owns the values of wind, night and sun.
- `src/core/events.js` (`app.events`): `bell {auto}`, `bell-request {urgency}`, `station-arrive {station, visit}`, `station-depart {station}`, `doors {open, visit}`, `tod {t}`, `start`, `tram-bell {unit, s, d}`, `ready`.
- `src/core/rng.js`: `RNG.from(...parts)`, `hash2`, `noise1/2`, `noise1p/2p` (periodic), `loopNoise1/2` (periodic in the loop length, no seam). Never use `Math.random()` for world content. The noises are allocation-free; hot paths that need several of them per call can use `lattice1/lattice2` + `LATTICE` (as `route.surface` does) to avoid boxed arguments.
- `src/core/geom.js`: `ribbonGeometry`, `sweepProfile` (CCW profile in (d, h)), `MeshBatcher`, `normalizeAttributes`, `setColor`.

## Materials: `app.materials` (`src/materials/materials.js`)
- `get(name, opts?)` returns a shared material. `opts` (for example `{vertexColors: true}`) returns a cached variant, shared by every module asking for the same options. Use vertex colours for per-building stone tint and baked AO.
- `register(name, material)` adds your own material to the library. `track(material)` is **required for every material you put in the scene**, so the lighting system can configure it (shadows/CSM/fog). `onTrack(fn)`, `all()`, `names()`, `meta[name]`, `ready` (resolves when the GPU-baked maps are final; `init` does not wait for the bake).
- Names (all must exist): `stone.ashlar`, `stone.smooth`, `stone.rough`, `stone.dirty`, `paving.street`, `paving.sidewalk`, `paving.band`, `paving.platform`, `rail.head`, `rail.side`, `rail.groove`, `metal.iron`, `metal.pole`, `metal.galvanized`, `metal.steel`, `metal.wire`, `metal.rust`, `glass.shop`, `glass.window`, `glass.lamp`, `fabric.awning`, `fabric.umbrella`, `fabric.flag`, `wood.shutter`, `wood.door`, `wood.bench`, `paint.frame`, `paint.frameDetail`, `wood.shutterDetail`, `plastic.chair`, `concrete`, `roof.tile`, `roof.membrane`, `plaster`, `bark`, `bark.smooth`, `leaf`, `rubber`, `asphalt`, `sign.panel`, `emissive.warm`. (`ironwork.ac` no longer exists: AC units use `ironwork.parts`.) `bark.smooth` is for trunks under about 25 cm and branches.
- `meta[name]` publishes metrics for other modules: tile sizes and uv conventions, `stone.ashlar` `{courseH, blockL, tints, tintWeights, albedo}` (mean linear albedo of the baked limestone, about `[0.6, 0.47, 0.27]`; stand-ins such as the far field match it), `paving.street.albedo` `[0.157, 0.168, 0.192]`, `paving.band.albedo` `[0.214, 0.213, 0.207]`, `rail.head` band layout, `stone.rough.relief`. A module that derives colours from a library albedo reads them from here rather than hard-coding them; env's canyon model assumes paving of about (0.17, 0.175, 0.185), so tell env when that changes substantially.
- Facade stone UVs: u = metres along the wall, v = metres up from `floorRef` (or world height), so ashlar courses line up across a facade.
- If you patch a material with `onBeforeCompile`, **chain** any existing hook (`const prev = m.onBeforeCompile; m.onBeforeCompile = (s, r) => { prev && prev(s, r); ... }`) and set `customProgramCacheKey`.
- One material object must not be drawn by both a `BatchedMesh` (or `InstancedMesh`) and a plain `Mesh`: three re-evaluates its program at every switch (CPU time and garbage each frame). Ask for a separate variant for the batched use.
- `envMapIntensity`: three ignores a material's `envMapIntensity` when the environment comes from `scene.environment` (it substitutes `scene.environmentIntensity`). Library materials honour it through their surface patch; on your own materials set `material.envMap` explicitly or scale the indirect specular in your shader.
- Surface features and program keys: the runtime surface patch (`src/materials/surface.js`) builds programs keyed `'sf7'` + `'S'` + the family's feature letters + per-material letters (A lane attribute, T translucency, N night emissive, G thin glass). Families: `lite`, `full` (`LJPDRWK`: stone, paving, concrete, plaster, roof tiles) and `relief` (`LDRWH`, key `sf7SLDRWH`, rock-faced stone only, selected by the library field `fx: 'relief'`). Feature H is parallax-occlusion relief of the height a recipe stores in the albedo alpha (`heightA: [lo, hi]`, metres encoded over lo..hi), marched through the row layout with a self-shadow march towards the sun and faded out with distance (full within about 20 m, gone by 35 m); roughness then comes from the height. `stone.rough` uses it: `meta.relief = [0, 0.095]` (the bosses stand up to 9.5 cm in front of the polygon), so signs, plates and lamps mounted over it stand off about 0.1 m; the outline of the mesh itself stays as modelled. `surf.stain.stretch` stretches stains vertically along v (run-off on walls).
- Night emission scales with `app.materials.uniforms.emissiveGain`: scale a module's night emissives with it rather than asking env to change the night ramp.
- `paving.street` accepts a `laneAttr` option.

## Lighting and image
### env (`src/env/env.js`, `src/env/lights.js`, `src/env/sky.js`)
Sky, sun, environment map, shadows, fog/haze, wind, time of day, exposure and the few real lights.
- `env.setTimeOfDay(t)` with t in [0, 1]: 0 midday, 0.55 golden hour, 0.8 sunset, 1 dusk. `env.state = {t, sunDir, sunElevation, night}`. It sets `U.uNight` (smoothstep over t 0.70–0.82, so the street lamps are fully on by sunset), `U.uSunDir`, `U.uSunColor` and `U.uWind*`, and emits `tod`.
- Weather (`env.weather`, URL `sky=`): `streaks`, `cumulus` or `haze`, picked from the seed by default. Each regime carries its own aerosol load and street dust haze (`haze` is visibly milky).
- Exposure: `env.exposureBase` is the nominal exposure (a 0.18 albedo under the horizontal illuminance, partial adaptation at dusk) lifted by `EXPO_LIFT` (+0.84 EV at midday, +1.2 EV at golden hour, back to 0 from t 0.78: a photograph of a sunny street exposes for the shade). `env.exposureMax` is the ceiling for the metered exposure, the minimum of three caps: the low-sun lit-stone cap (from about t 0.35, sun-facing stone stays on the tone curve's shoulder), the horizon cap (holds the sky slot down the street at `HORIZON_LEVEL`) and the dusk ceiling (from t 0.62: at most 1.8× the nominal exposure up to t 0.82, 4.2× in the blue hour). `env.exposure = min(exposureBase, exposureMax)`.
- Colour outputs for post: `env.illuminant` (sun + sky on a horizontal surface in the open) and `env.sunIlluminant` (the direct sun alone, `U.uSunColor`). `env.skyIrradianceH` is the sky irradiance luminance on a level surface; shaders may read it instead of sampling the environment map.
- Lights (`env.lights`): a pool of real spot lights, one per lantern (12 on high, 8 on med, 4 on low), reassigned every frame to the nearest lamp standards at dusk, plus `farLamps` (24 distant standards for post's screen-space pools). The shared light loop skips dark lights (colour 0) and spot lights outside their cone or range, so permanent light slots cost nothing when off. The headlight is the tram's dipped beam, told apart in the light loop by its decay `2.0001`: other modules must not create spot lights with decay above 2.00005.
- A canyon-bounce hemisphere light adds warm fill from sunlit stone. Next to it, env's `canyonCrossBounce` DirectionalLight carries the light of the sunlit facade across the street to the opposite one: horizontal, aimed at the camera from the sunlit side, coloured by the sunlit facade's reflected irradiance, and black (skipped) when no facade is in the sun. It stands for a 10–20 m area source, so it is **diffuse only**: the shared light loop puts back whatever `RE_Direct` adds to the specular, clearcoat and sheen terms for `directionalLights[]`, for every lighting model including patched ones (a specular term showed as white smudges in shop glass). It is the only entry of `directionalLights[]`, because the sun is a `SunLight` (`sunLights[]`). A module must not add a DirectionalLight of its own expecting speculars, and a custom shader that loops over `directionalLights[]` outside `RE_Direct` must take only the diffuse term.
- The environment cube holds a model of the street canyon (facades, floor, sky slot); it is the canyon occlusion for every glossy surface (rail steel, glass, paint). The trams compensate in their own shader for its bright, empty street level.

### Shadows (env)
- The sun uses 4 cascades in one atlas row, fitted to the field of view; its shadow camera reaches 700 m. Beyond it the far field shades its own street as a canyon (see World module contracts). Cascades 0-1 redraw every frame, cascade 2 every 2nd frame and cascade 3 every 4th; all redraw on camera or sun moves.
- Cascades 2-3 skip `mesh.userData.thinCaster` meshes and casters under 1.5 texels. A numeric `thinCaster` is the largest cascade texel (m) at which the caster still draws.
- Static casters in a ready chunk are merged in the background into depth-only proxies. Set `mesh.userData.dynamicCaster = true` to keep a mesh out of merging; changes are detected automatically anyway.
- Instanced casters may set `mesh.userData.shadowRange = [minViewDepth, maxViewDepth, margin]` each frame so cascades they cannot reach skip them.

### post (`src/env/post.js`): `render(dt, app)`, `setSize(w, h)`
HDR scene (MSAA, sub-pixel jitter) → SSAO → clouds → prepass (aerial perspective, shimmer, dusk airlight and lantern wash, circle of confusion; broken pixels filled) → TAA → DOF → motion blur → bloom → metered exposure → lens, sharpening, white balance, tone curve, grain.
- Tone: a camera tone curve (long toe, soft shoulder) with AgX colour, a little extra contrast at midday (easing off by t 0.5), and a soft black point `uBlack` (0.032 by day, 0.012 from t 0.6–0.85). Sky pixels (depth = far) keep nearly the scene's colour ratios (chroma 0.95, URL `skychroma`), get a saturation boost (1.2 by day to 1.05 at dusk, URL `skysat`), skip split toning and have their own saturated-sky gamut knee.
- Exposure: the final pass applies `min(uExposure × corr, uExposureMax)`, where `corr` is the meter's correction (by day the exposure follows the incident light and the meter only nudges it; from the low sun on the camera meters the scene) and `uExposureMax` is `env.exposureMax`.
- Highlight recovery: `uHiComp = (knee, slope)` compresses luminance above the knee in log terms with a soft knee. Knee (stops over mid grey): +1.6 by day, +1.2 at golden hour, +1.0 at sunset. Slope: 1 (off) at midday, 0.5 by t 0.3, 0.34 at golden hour, 0.27 at sunset, opening to 0.6 at dusk (URL `hslope` overrides it).
- Lens veil (final pass): `uVeil` (0.006) × the frame's mean HDR colour, which the LUM pass stores in `.gba` (`.r` holds the metering log-average), plus `uVeilSun`: the sun's colour × 0.0012 × sun intensity × exp(−angle / 0.25 rad) while the camera stands in sunlight (env's canyon shadow plane).
- White balance (`uWB`), on a warm-cool and a green-magenta axis. By day it balances on `env.sunIlluminant` (a daylight preset: sunlit grey paving reads neutral, the shade keeps its blue), correcting under a third of the sun's cast; between t 0.3 and 0.6 it blends to `env.illuminant` and keeps most of the evening warmth; from sunset (t 0.78) there is no warm-cool correction at all (a daylight-balanced camera: the lamp pools stay amber, the twilight blue), with a little extra blue in the blue hour. The gains stay on the daylight locus: the green gain within [0.99, 1.03] × sqrt(gR·gB), a neutral surface under the illuminant at G / mean(R, B) in [0.97, 1.0], and once the lamps light the street the green gain stays within 12 % of the red one (amber pools, never olive). Lit interiors and shop windows keep the warmth they are given at night.
- Lantern wash (prepass, at dusk): `uWash` (0.08 × night) adds each real lamp light's sideways and upward glow (`uLampPos`/`uLampI`, outside the spot cone, about 16 m reach) in screen space, on surfaces within 140 m of the camera (depth-reconstructed normal, albedo estimated from the ambient-lit colour). Beyond the real lights, `uFarLamp`/`uFarI` (from `env.lights.farLamps`) add the distant lamp pools the same way.
- Bloom: a share of the blurred pyramid (0.018 by day to 0.04 at night); at night a coarse pyramid level adds a wide tail (`uTail`).
- Temporal AA: the scene pass is rendered with a sub-pixel Halton (2, 3) jitter in the projection matrix (16 samples, `taaj` px peak to peak, default 0.5) and resolved against a reprojected history (new-frame weight 0.1, variance clipping). The history resets on cuts, jumps over 4 m and zooms. Only the projection is jittered: `projectionMatrixInverse` and the shadow cascades fitted from it stay unjittered. Frame-varying dither in a material (alpha hash, stochastic fades) averages out over about 10 frames, while a pattern fixed in screen space stays visible. URL: `taa=0`, `taaj=<px>`, `sharp=<k>` (final luma sharpening, default 0.8).
- `post.history` = `{texture, viewProj, camPos, fov, valid}`: the last resolved frame (scene-linear HDR before exposure) with its unjittered view-projection, camera position and field of view; `valid` is false while there is none (TAA off, a cut). Read it during the update phase, before the frame renders. The oncoming trams' glazing, windscreen and clear coat reflect the street from it (falling back to `taaOn/taaRT/taaPing/prevVP/taaValid/prevCamPos/prevFov`, so those names stay stable too).
- Motion blur: camera blur from `cameraRig.prevViewProj`, `cut` and `shutterSec`, capped at `cameraRig.blurMaxPx` (default 32 px at 1080 lines). The oncoming trams also blur and reproject correctly in TAA: post reads `app.trams.units[]` (`id, s, d, length, halfWidth, active, root.visible`) and moves two route-following boxes per unit within 200 m (a jump over 6 m resets a unit's history). Figures have no per-object motion yet; a module that wants it publishes per-object previous positions in the same shape.
- SSAO scales `app.materials.uniforms.aoScale` to 0.6 while it runs. DOF models a 1"-type sensor: f/8 by day, f/2.8 at dusk.
- `debug=1`: post counts broken scene pixels (non-finite or negative HDR values) every 30 frames and reports the count as `stats().badPixels`. The read-back stalls, so this is for debug runs only. Post fills such pixels, but any non-zero count is a shader bug to fix at its source (for example a normalize of zero or a negative light value).

## Ride and people
- **train** (`src/ride/train.js`): `app.train = {s, speed (m/s), accel, throttle (−1..1), auto, state ('run'|'brake'|'dwell'|'depart'), nextStop, curvature, cruise, bellAt, t, holding, coasting, pedLoad, corridorCount, tram}`. `s` is the cab front along the route; `t` is the simulation clock. `holding` is true until the world is ready and, in the interactive app, until the start click: the tram doesn't move meanwhile. An interactive run without `speed=` starts standing and departs with a bell after the click; `speed=` only sets the starting speed.
  - The automatic driver cruises at 40–45 km/h on a clear corridor and 23–28 km/h when it is busy (`Tram.setLoad`: the weighted count of people in the corridor 5–200 m ahead, `corridorCount`, sampled every second and smoothed over about 5 s into `pedLoad` 0..1). The oncoming units do the same.
  - Obstacles: `app.train.tram.setObstacle(m, source)` reports the distance (m ahead of the cab front; Infinity: none) to somebody on the track who will not be clear in time. The nearest report of every source that reported within 0.5 s counts, and the tram stops 5 m short of it (emergency brake if needed, after a confirming fraction of a second; held for long, the driver rings and creeps up). Assigning `tram.obstacle` is the same as source `'direct'`; the crowd writes it every frame for the cab tram.
  - `station-arrive` and `doors` carry `{visit}`, and `station-depart` fires when the tram actually moves off. A `bell-request` urgency is held for 3 s.
- **cameraRig** (`src/ride/cameraRig.js`): sets `app.camera` from the train state and **must set `app.cameraS`**. The camera is body-mounted: the eye is 1.7 m behind the cab front, so `cameraS = train.s − 1.7`, and it carries sway, bob, joint impacts and mouse look (grab-style drag). The view is fixed to the cab at every zoom, like a mounted cab camera: it never pans towards the line ahead, so the ride rails stay under the middle of the frame and the line sweeps across the frame in bends (`RIG.headTurn` / `teleHeadTurn` are 0). It exposes `yaw`, `pitch`, `fov` (16:9-equivalent vertical), `prevViewProj`, `cut`, `shutterSec` and `blurMaxPx` for post. **The tram is never rendered: no cab, console or windscreen at any zoom.** The shared axle table lives in `src/core/config.js` (`AXLES`). Keys: `M` mutes, `F` toggles full screen.
- **trams** (`src/ride/trams.js`, oncoming units): `app.trams.units[]` = `{id, s, prevS, speed, accel, dir (−1), d (−TRACK_OFFSET), length (32), halfWidth (1.325), state, phase, bellAt, active, obs, root}`. `s` is the leading nose on the route; the body trails towards +s, and the unit travels towards −s. They drive the same vehicle and driver model as the cab tram, stop at the left platforms, scan for people on their track (their own obstacle source) and ring and creep when held. Their glass and paint reflect the street from `post.history`, and the saloon interiors are traced in the glass shader. Event `tram-bell {unit, s, d}`. Keep the published unit fields stable: post, the crowd and catenary read them.
- **humans** (`src/crowd/humans.js`) renders the figures, and **crowd** (`src/crowd/crowd.js`) decides where they go:
  - `app.humans.alloc(count)` then `app.humans.set(i, {x, y, z, heading, speed, phase, pose, look, appearance, visible})` per frame for active agents, or `setVisible(i, false)`. `pose`: 0 walk/stand blend by speed, 1 stand idle, 2 sit, 3 pushing a stroller, 4 riding a bicycle, 5 walking beside a bicycle. `prop` = 0 none, 1 stroller, 2 bicycle, and `propSeed` picks the model variant and colour. `appearance` is an integer seed: the renderer derives sex, height (1.50–1.95 m), build, skin, hair and clothing from it. `heading` is world yaw in radians where 0 faces −Z, matching three.js `rotation.y`. The renderer exposes `strideLength(appearance, speed, pose)`, `cycleLength(appearance)` (metres per crank revolution) and `heightOf(appearance)`, so the crowd advances `phase` without foot sliding.
  - Props are rendered and animated by humans, attached to the figure: bicycle wheels roll with distance, cranks turn with `phase`, and stroller wheels roll. Footprints for avoidance: a bicycle is about 1.8 m long centred on the rider, and a stroller extends about 1.1 m ahead of the person. humans also builds the **parked bicycles** (its own `build(chunk)`) at `bikeRack` furniture positions and occasionally leaning on poles/trees.
  - The crowd uses `layout.obstacles` and cafés (seated patrons at the set places), platforms (waiting passengers), side streets (people up a side street walk and are drawn in its mouth frame, see Ground), the pedestrian signals (`catenary.signalAt`), `app.train` and `app.trams.units` to clear the tracks ahead of every tram. Nobody may ever intersect the camera (with `view=` the free camera is an obstacle like a pole). It emits `bell-request` and reacts to `bell`, and it writes the cab tram's obstacle (`app.train.tram.obstacle`, see train).
  - Pair rule: where the cab and an oncoming unit pass a spot within 3 s of each other, the whole corridor is cleared to its edges, and nobody uses the space between the tracks (|d| < 0.9) as a refuge while a unit is within 120 m.
  - Café waiters are agents with `role: 'staff'`. Crowd stats: `stats().standing`, `sideStreets`, `units`, `mobility`, `corridorDirs`, `events.waiter`; with `crowdCheck=1` the `check` block adds swept-volume, obstacle and facade checks, `check.squeeze` (agent-frames between the tracks while the cab and a unit go by each other) and prop checks.
- **audio** (`src/ride/audio.js`): WebAudio synthesis only. It starts on the first user gesture (`app.events` `start` from ui) and reads `app.train` (speed, curvature, state) and `app.camera`.
- **ui** (`src/ride/ui.js`): DOM in `#ui-root`. Shows the speed readout, throttle state, time-of-day slider and FOV control, H to hide, and a start overlay ("click to ride"), which emits `start`. Everything is hidden when `capture=1`.

## World module contracts
- **catenary** (lamps, catenary, signals): `app.systems.catenary.signalAt(s)` returns the pedestrian light at the crossing nearest route s within 15 m: `'red'`, `'flash'` (green that turns red within 3 s) or `'green'`, or null where there is none. `pedState(sc)` gives the state of the crossing at sc as 0 red, 1 flashing, 2 green (memoised per frame). The lights are red while a tram front (the cab tram or a unit) is within about 60 m or 8 s of the crossing or its body is over it, then flash green for 3 s, and are green the rest of the time. Walkers wait at the kerb on red, do not start crossing on flash, and cross freely on green. The lantern globes have a radiance of about 0.11 scene units (warm white; they bloom to white at night, as real globes do) and switch on with their own photocell ramp from t 0.64 (full by 0.72), ahead of `uNight`.
- **facades**: dresses every lot's openings, shopfronts, signs, awnings and backdrop lots. Every café terrace is centred on a ground-floor shop of its lot (`layout.cafes[lot.cafe]`), which the facades make a café shopfront. `shopDecision(plan, o)` is the door and shutter decision (see Module system).
- **furniture**: café furniture (writes `dressed`, `places` and relaxed positions back into the layout at init), platforms and shelters, benches, kiosks…, sidewalk A-boards beside about one shopfront in five (`furniture/shopStands.js`, planned at init and registered as crowd obstacles), and parked vehicles on the side-street carriageways 15–60 m from the mouth (`furniture/vehicles.js` `planMouth`: walkers deeper than 15 m into a side street keep to its sidewalks).
- **buildings**: shells, masonry relief and its own dressing of `plan.upper`; `extraLots()` for backdrop lots dressed by facades; mural and advert materials on party walls.
- **far field** (`src/core/farfield.js`, core, lod 2 only): the city beyond VIEW_AHEAD, built from the same plans: every lot a block of its plan's height in its stone colour (`materials.meta['stone.ashlar'].albedo` × the tint), rendered lots in their wash over a stone shop floor, cornice, balconies, openings (lit at dusk), tile roofs, set-back volumes with their balconies, and towers with their side windows and the mural as a flat panel of its average colour; paving with the corridor bands and the side-street mouths; trees and lamp standards. Beyond the sun's shadow range it shades itself as a street canyon in cross-section: per vertex it carries its lateral offset, height and the street's right vector (`aCy`) and the facade lines and block heights on both sides (`aCw`, no block in a side-street mouth), and the sun light alone is cut where the ray towards the sun passes below the block on the sun's side, so the far floor and lower facades keep the shade split of the street before them. One merged mesh, one material and one draw call per far chunk, no shadow casting; ride-time build about 1 ms. Party-wall adverts are left out.

## Streaming (`src/world/streaming.js`)
- Chunks within VIEW_BEHIND (60 m) behind to VIEW_FAR ahead are kept; builds are time-sliced (about 7 ms per frame), nearest first; chunks crossing a level boundary are rebuilt at the finer level and swapped in when ready (no gaps). A far chunk is replaced by the full chunk at VIEW_AHEAD, and parts of the old chunk with no counterpart (the far field) hide at the new chunk's first reveal.
- `app.world.upcoming(sCam, lookAhead = 0, out?)` lists the chunks the streamer will build next, `[{index, lod, dist, future}]` nearest first, including those that will be wanted, or upgraded to lod 0, within `lookAhead` metres of travel. It never lists lod 2. Pass an array of your own as `out` when you call it every frame: it is refilled in place, reusing its entries, so the call makes no garbage. `readyAround(s, dist)` ignores lod 2 as well.
- `stats().rideBuild` gives per-module ride-time build p50/p95/max over the last 200 builds; startup builds are excluded.
- New chunks compile their programs in the background before they are shown, then their parts reveal under a per-frame upload budget (4 MB). A module that pre-uploads vertex data can set `geometry.userData.revealBytes` to the bytes a reveal still sends.

## Shared-batch pattern (ironwork, reusable)
`build()` returns an empty marker group, and the meshes live in one scene-level group. A chunk's content starts drawing when its marker group becomes visible (or when it replaces an upgraded chunk) and is released on dispose. Shadow stand-ins are culled per block with the light's cascade frustum. BatchedMeshes should create their colour texture up front, so the startup compile doesn't build programs for empty batches.

## Frame timing, garbage and budget
**Budget (1920×1080; quality first, 30 fps minimum, 60 fps nice-to-have).** Photorealism has priority: spend headroom on image quality (shadow resolution and softness, AO, AA, geometric detail, crowd density) as long as the whole frame stays ≤ ~28 ms GPU / ≤ 20 ms CPU on this machine (RTX 4060 Ti) and riding has no hitches > 60 ms.
- Draw calls under ~1500 including shadow passes. Keep triangles reasonable (under ~10 M including shadows) and avoid aliasing at all costs.
- Per chunk per module: build under 3 ms (lod 0), under 1 ms (lod 1). Prefer instancing and merged geometry. LOD 1 (over 200 m) should be much lighter: no small details that would sub-pixel alias at that distance.
- Thin geometry (wires, railings) must not alias or shimmer. Use pixel-width-aware shading or fade for far wires, and alpha-to-coverage with coverage-preserving mips or textures for fine ironwork and foliage far away.

**Frame monitor (`src/core/frameMonitor.js`).**
- `stats().frames` gives `{n, p50, p95, p99, max, over50, over60}`, the frame intervals in ms since ready (or since `app.resetFrames()`). `stats().hitches` counts frames over 50 ms.
- `app.hitches()` returns one record per frame interval over 50 ms (the newest 120). Each record has the route position and speed, the interval, the frame's CPU time and the gap outside the frame callback, and the CPU time of each stage (every module's `update`, `world` streaming and `render`) next to its `usualStages` value. The usual value is the median of the last 128 smooth frames. The record also has the shadow-pass CPU time and the cascades redrawn, the programs created in the frame (`syncCompile` counts those created inside render), the chunks compiling, the bytes revealed, whether a shadow-proxy merge ran, draw calls, the heap drop (a garbage collection), the frame's GPU time, post's section timers under `prof=1` and the browser's long-animation-frame script attribution. `app.hitchReport()` prints all of this one line per hitch, and `shoot.py --hitches` uses it.
- `cause` is a best guess: `sync-compile`; `contention` (every module update ran several times over its usual time at once, so the main thread was starved by other processes and no code path is to blame); `gc` / `gc-in-<stage>`; `gpu-wait` (render alone took several times its usual CPU for the usual draw calls, so the main thread waited on the GPU: on a shared machine, usually another process's GPU work); `cpu:<stage>` (one stage explains the excess: look at that module); `task:<fn>` (a timer or promise callback between frames); `idle-wait` (GPU or compositor back-pressure). Whatever the cause, `spikes` lists the modules that ran over 4× their usual time plus 5 ms, and the report header counts them per module. A module that keeps showing up there has a work unit that is too long for one frame and should split it; a prefetch budget must be a fixed number of milliseconds, not one that grows with a slow frame's `realDt`.

**Garbage.** A major collection pauses the main thread for 20–50 ms, so per-frame code must not allocate:
- No closures, arrays or objects per call in hot loops; pass `out` vectors and reuse scratch objects. `Array.prototype.sort` copies its array on every call: sort short per-frame lists with a small insertion sort.
- Numbers are garbage too: a non-inlined call boxes its float arguments and a float return value (and a uint32 above 2^30, such as a hash). Keep tight loops inside one function, write `v.x = …` rather than calling `v.set(…)` with computed floats in the hottest paths, and read results out of typed arrays. `Math.hypot` with three or more arguments allocates; use `Math.sqrt(x*x + y*y + z*z)`.
- A transparent `DoubleSide` material without `forceSinglePass = true` is drawn in two passes, and three re-evaluates its program on each one. The same happens to a material shared between instanced or batched and plain meshes (see Materials). Each re-evaluation builds a parameter object and a cache-key string.
- Uniform uploads: three uploads a few thousand vector uniforms a frame (the lights move in view space with the camera, once per program). Core routes `gl.uniform1f…4f` through the vector forms with one reused typed array (URL `glbox=0` turns it off for A/B), which removes part of the float boxing at the browser boundary.
- Use `shoot.py --heapprof` to find allocation sites; compare per frame.
